# パフォーマンス最適化

Adbx Engine Editorのパフォーマンス最適化について説明します。

## 大規模シーンでのパフォーマンス改善

### 仮想スクロール

ヒエラルキービューとアセットブラウザーでは、仮想スクロールを実装しています。表示範囲外のアイテムはレンダリングされないため、大量のエンティティやアセットがある場合でもパフォーマンスが維持されます。

### バッチ処理

シーン読み込み時には、エンティティの作成をバッチ処理で行います。これにより、大規模なシーンの読み込み時間を短縮できます。

## エディタUIの応答性向上

### 遅延更新

インスペクターパネルでは、更新を100ms間隔でスロットルしています。これにより、Transformの連続的な変更時でもUIの応答性が維持されます。

### 変更検知

不要な再描画を防ぐため、変更検知システムを実装しています。実際に変更があった場合のみUIを更新します。

## Luaスクリプト実行の最適化

### スクリプトキャッシュ

スクリプトのコンパイル結果をキャッシュし、スクリプトの内容が変更されていない場合は再コンパイルをスキップします。

### 実行頻度制限

エンティティごとに実行頻度を制限できます（デフォルト60FPS）。これにより、不要なスクリプト実行を削減できます。

### 不要な実行のスキップ

`update`関数が定義されていないスクリプトは、自動的に実行をスキップします。
