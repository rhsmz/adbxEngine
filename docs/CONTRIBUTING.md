# コントリビューションガイド

Adbx Engine Editorへのコントリビューションをありがとうございます。このドキュメントでは、ドキュメントの更新方法と責務について説明します。

## ドキュメントの更新

### ドキュメント構造

ドキュメントは`docs/`ディレクトリに以下のように配置されています：

```
docs/
├── api/              # APIリファレンス
│   ├── editor/       # エディタAPI
│   ├── runtime/      # ランタイムAPI
│   └── shared/       # 共有API
├── architecture/     # アーキテクチャドキュメント
├── developer-guide/  # 開発者ガイド
└── user-guide/       # ユーザーガイド
```

### 更新が必要な場合

以下の変更を行った場合は、対応するドキュメントを更新してください：

1. **新機能の追加**: ユーザーガイドとAPIリファレンスを更新
2. **APIの変更**: APIリファレンスを更新
3. **アーキテクチャの変更**: アーキテクチャドキュメントを更新
4. **ビルド/実行手順の変更**: ユーザーガイドの「はじめに」を更新
5. **既知の問題の追加**: `developer-guide/known-issues.md`を更新

### ダイアグラムの作成

技術的なダイアグラムはKrokiを使用して作成します。

#### Krokiの使用方法

1. **Kroki Docker環境の起動**:
   ```bash
   cd docs/kroki-docker
   docker-compose up -d
   ```
   サービスは`http://localhost:8000`で利用可能になります。

2. **ダイアグラムの記述**:
   Markdownファイル内で以下の形式を使用します：
   ````markdown
   ```kroki-plantuml
   @startuml
   // PlantUMLコード
   @enduml
   ```
   ````

3. **サポートされている形式**:
   - PlantUML（クラス図、シーケンス図、ユースケース図など）
   - BlockDiag（ブロック図、ネットワーク図）
   - Diagrams.net（フローチャート、ダイアグラム）

4. **ダイアグラムの確認**:
   テキストをBase64エンコードして直接URLで確認できます：
   ```bash
   # PlantUMLの場合
   echo "@startuml\nclass Example\n@enduml" | base64 -w 0
   ```

詳細は[Kroki Docker環境のREADME](kroki-docker/README.md)を参照してください。

#### ダイアグラム更新のタイミング

- 新しいアーキテクチャ要素が追加された場合
- APIの関係性が変更された場合
- データフローが変更された場合
- 新しいUIコンポーネントが追加された場合

### ドキュメントの更新手順

1. **変更内容の確認**: ソースコードの変更を確認し、影響を受けるドキュメントを特定します
2. **ドキュメントの更新**: 該当するMarkdownファイルを編集します
3. **ダイアグラムの更新**: 必要に応じてKrokiダイアグラムを更新します
4. **リンクの確認**: 内部リンクが正しく機能することを確認します
5. **レビュー**: 変更内容をレビューします

## 責務

### ドキュメントメンテナー

- ドキュメントの品質管理
- 定期的なドキュメントのレビュー
- 古い情報の更新

### 開発者

- コード変更時の対応するドキュメントの更新
- 新機能のドキュメント作成
- バグ修正時のトラブルシューティングドキュメントの更新

## ドキュメントの品質基準

### 必須項目

- **正確性**: コードと一致していること
- **完全性**: 必要な情報がすべて含まれていること
- **明確性**: 読みやすく理解しやすいこと
- **最新性**: 最新のコードに基づいていること

### 推奨項目

- **例の提供**: コード例や使用例を含める
- **図解**: 複雑な概念はダイアグラムで説明する
- **トラブルシューティング**: よくある問題と解決方法を記載する

## チェックリスト

ドキュメントを更新する際は、以下のチェックリストを確認してください：

- [ ] コードの変更内容を正確に反映している
- [ ] 既存のドキュメントとの整合性が取れている
- [ ] リンクが正しく機能している
- [ ] ダイアグラムが最新の状態である
- [ ] スペルチェックと文法チェックが完了している
- [ ] 例が実際に動作することを確認している
